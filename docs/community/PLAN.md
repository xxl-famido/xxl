작성 2026-09-28. 상태: **v1 — 사용자 결정 반영(§9), L1 목업 진행**. 정식 명칭 **XXL 라운지**. 시뮬레이터 v2 개편(`docs/redesign/PLAN.md`)과 같은 토큰·원칙(`DESIGN_PRINCIPLES.md`)·용어(`GLOSSARY.md`)를 따르고, 그 위에 읽기·쓰기 중심의 전용 레이아웃을 얹는다.

## 1. 한 줄 정의

시뮬레이터 옆에 붙은 **별도 창**. 로그인 없이 익명으로 "익명의 ○○(동료 이름)"가 되어
① 동료마다 의견을 남기고 ② 나만의 티어표를 만들어 공개하고 ③ 공유 코드로 팀을 올린다.
세 기능은 따로 놀지 않고 **동료 페이지로 모인다** — 동료 페이지에서 그 동료의 의견·커뮤니티 티어·그 동료가 들어간 팀을 한 번에 본다.

## 2. 정보 구조

```
라운지 (community.html — 시뮬과 별도 문서, tokens.css 공유)
├─ 동료 게시판  [메인]
│   ├─ 동료 목록        #/            42명 격자 + 속성·포지션 필터 + 검색 + "최근 의견 많은 동료"
│   └─ 동료 페이지      #/c/10441     헤더(일러스트·속성·포지션) → 요약 띠 → 의견 스레드
├─ 티어표  [사이드]
│   ├─ 모아보기         #/tier        공감순/최신, 기준(종합·보스전·방탈출) 필터 + 커뮤니티 평균 티어
│   ├─ 만들기           #/tier/new    드래그 편집기
│   └─ 보기             #/tier/:id    읽기 + "가져와서 수정" + 이미지 저장 + 의견
├─ 팀 공유  [사이드]   (사용자 표현 "조합" — 용어집 기준 공식 표기는 "팀", §9-4)
│   ├─ 모아보기         #/team        공감순/최신, "이 동료 포함" 필터(최대 3명 AND), 기준 필터
│   ├─ 올리기           #/team/new    공유 코드 붙여넣기 → 자동 판독 미리보기 → 설명 작성
│   └─ 보기             #/team/:id    5인 프로필 + 설정 요약 + 설명 전문 + "시뮬하러 가기" + 의견
└─ 내 활동              #/me          이 기기에서 쓴 글·티어표·팀, 기기 코드 백업/복원
```

- 데스크톱: 좌측 고정 사이드바(동료 게시판 / 티어표 / 팀 공유 / 내 활동) + 본문 1열(최대 폭 760px, 읽기용). 동료 페이지는 우측에 보조 열(커뮤니티 티어, 포함 팀 top 3).
- 모바일 390px: 사이드바 → 하단 탭 4개. 보조 열은 본문 요약 띠로 접힌다.
- 시뮬 ↔ 라운지 연결:
  - 시뮬 상단 바에 "라운지" 링크(새 창 아님, 같은 탭 이동 + 시뮬 초안은 이미 자동 저장됨).
  - 시뮬 결과 화면에 "팀 공유에 올리기" → `#/team/new?code=…` 로 공유 코드를 채워서 이동.
  - 라운지의 모든 팀 → "시뮬하러 가기" = `index.html#code=…&run=1` (불러온 뒤 자동 실행).
  - 시뮬 동료 목록의 동료 상세에 "의견 N" 링크 → `#/c/:id`.

## 3. 익명 정체성 "익명의 ○○"

| 항목 | 설계 |
|---|---|
| 기기 식별 | 첫 방문 시 128bit 난수 `device_token`을 localStorage(`woofia_lounge_dev`)에 생성. 서버에는 `sha256(token + 서버 비밀값)`만 저장 |
| 이름 뽑기 | `HMAC(서버 비밀값, 기기해시 + 스레드키)` → 42명 중 1명. **같은 스레드 안에서는 같은 이름 유지**, 다른 스레드에서는 다른 이름(스레드 간 추적 방지) |
| 충돌 | 같은 스레드에서 다른 사람이 같은 동료를 뽑으면 `익명의 파미도 2` 번호 부여 |
| 표시 | 아바타 = 그 동료 아이콘(원형 24px). 이름은 **동료 ID로 저장**하고 보는 사람 언어로 렌더 → 일본어 사용자에겐 "匿名の○○" |
| 작성자 표식 | 스레드 주인(티어표·팀 작성자)이 댓글을 달면 "작성자" 칩 |
| **4자리 비밀번호** (사용자 결정) | 글·댓글·티어표·팀을 쓸 때 숫자 4자리 비밀번호를 정한다. 이 비밀번호로 ① 수정 ② 삭제 ③ **이어 쓰기** — 같은 스레드에서 비밀번호를 입력하고 답글을 달면 처음 쓴 글과 **같은 익명 이름**으로 달린다(기기를 바꿔도 가능). 기기 무관 |
| 비밀번호 보안 | 서버에는 글마다 salt + scrypt 해시만 저장. 4자리는 1만 가지라 **대상 글 기준 오답 5회 → 1시간 잠금**, IP해시 기준 전역 제한 병행. 이 기기에서 쓴 글은 비밀번호를 기억(선택, localStorage) |
| 내 글 관리 | `#/me` = 이 기기에서 쓴 글 목록(localStorage의 글 ID). 수정·삭제는 비밀번호로 |
| 보이지 않는 것 | IP·UA 원문 저장 안 함. 도배 방지용 IP는 `sha256(ip + 일자별 salt)`로 24시간만 |

## 4. 기능 상세

### 4-1. 동료 게시판 (메인)

**동료 목록 `#/`**
- 42명 일러스트 격자(갤러리 컨셉 그대로). 각 칸 아래 이름 + 의견 수. 신규 출시 동료는 "신규" 칩(출시 후 14일).
- 상단: 검색, 속성 점 필터, 포지션 세그먼트, 정렬(기본 순 / 최근 의견 / 의견 많은 순).

**동료 페이지 `#/c/:id`**
1. 헤더: 일러스트, 이름, 속성·포지션, "시뮬에서 편성" 버튼.
2. 요약 띠(한 줄): 커뮤니티 평균 티어(기준별) · 의견 수 · 이 동료 포함 팀 수. 각 항목은 해당 목록으로 가는 링크.
3. 의견 작성 칸: 본문(최대 1,000자) + 선택 태그(최대 2개 — `육성`, `보스전`, `방탈출`, `팀 구성`, `스킬 해석`. 문구는 용어집 확정 후).
4. 스레드: 정렬 **추천순(기본)**/최신. 댓글 → 답글(대댓) 2단계 표시, 답글의 답글은 같은 줄에 `@익명의 ○○` 멘션으로 이어 붙임. 신고.
   - **좋아요 / 싫어요** (사용자 결정): 좋아요 수는 보인다. **싫어요 수는 보이지 않는다.** 점수 = 좋아요 − 싫어요, 추천순은 점수(+ 최신 가중치, §4-4)로 정렬 → 점수가 낮은 글은 다른 글보다 아래로 내려간다. 1기기 1표(좋아요·싫어요 중 하나, 취소·전환 가능).
   - 각 의견에 **작성 당시 게임 빌드**(예: 0922) 표기. 이후 해당 동료 밸런스가 바뀌면 이전 빌드 의견은 "이전 버전" 칩으로 약하게 표시(삭제 안 함).
   - 긴 의견은 6줄 클램프 + "더 보기".
   - 태그 필터 칩(태그를 누르면 그 태그만).

### 4-2. 티어표 (티어메이커)

**편집기 `#/tier/new`**
- 기본 행 S / A / B / C / D + 미배치 풀(42명 전부). 행 라벨 문구·행 수(3~8) 편집 가능, 행 색은 쓰지 않는다(원칙 1 — 라벨 글자로만 구분).
- 드래그 앤 드롭(포인터 이벤트 직접 구현, 터치 지원) + 키보드 대체(동료 선택 → 숫자키 1~8로 행 이동). 모바일은 탭→행 탭 방식.
- 메타: 제목(40자), 기준(종합 / 보스전 / 방탈출 / 자유), 설명(1,000자), 게임 빌드 자동 기입.
- 초안 자동 저장(localStorage `woofia_lounge_tier_draft`).
- **이미지로 저장**: canvas로 PNG 생성(로컬, 서버 불필요) — 디스코드 등에 붙여 넣기용. 하단에 사이트 주소 한 줄.
- 공개 안 하고 "내 기기에만 저장"도 가능.

**모아보기 `#/tier`**
- 상단: **커뮤니티 평균 티어** — 기준별로 공개 티어표를 집계(각 티어표에서 동료 위치를 0~1로 정규화 → 중앙값 → S~D 재구간화, 표본 수 표기, 표본 5 미만 동료는 "표본 부족"). 기간: 현재 빌드 / 전체.
- 목록은 카드 반복 대신 **행 목록**: 제목 · 기준 · 작성자 익명 이름 · 공감 · 상위 티어 미리보기(작은 아이콘 한 줄).

**보기 `#/tier/:id`**: 읽기 전용 표 + 설명 + 의견 스레드(동료 게시판과 같은 컴포넌트) + "가져와서 수정"(내 편집기로 복제, 원본 링크 유지) + 이미지 저장.

### 4-3. 팀 공유

**올리기 `#/team/new`**
1. 공유 코드 붙여넣기 → **즉시 클라이언트에서 판독**(`src/core/codec.js` 재사용). 실패하면 "코드를 읽을 수 없음" 1줄 + 다시 붙여넣기.
2. 자동 미리보기 — 5인 프로필 이미지(행동 순서대로, 동료 아이콘 + 이름 + 성급/진화 등 코드에 있는 스펙), 속성 구성 점, 설정 요약(보스·턴 수·제단 사용 여부 등 코드에 들어 있는 것만).
3. 작성자 입력: 제목(40자), 기준(보스전 대상 / 방탈출 / 자유), 설명(3,000자, 줄바꿈 유지), 비밀번호 4자리. **수치 입력 없음**(사용자 결정 — 팀 구성과 설명만).
4. 서버도 같은 코덱으로 다시 판독해 동료 목록을 **서버가 결정**(클라이언트가 보낸 동료 목록은 믿지 않음). 같은 코드가 이미 있으면 "이미 공유된 팀" 링크를 보여 주고 중복 등록 막음.

**모아보기 `#/team`**
- 행: 5인 아이콘 줄 · 제목 · 설명 2줄 클램프("더 보기"는 상세로) · 기준 · 공감 · 의견 수.
- 필터: "이 동료 포함"(동료 1~3명 선택, AND), 기준, 현재 빌드만.
- 동료 페이지에서 "이 동료 포함 팀"으로 바로 필터된 채 진입.

**보기 `#/team/:id`**
- 5인 프로필 크게 + 설정 요약 + 설명 전문 + 공유 코드(복사 버튼) + **"시뮬하러 가기"**(primary).
  - 동작: `index.html#code=<공유코드>&run=1` 로 이동 → 시뮬이 코드를 불러온 뒤 **자동으로 실행**. (시뮬 v2 쪽 작업: 부트 시 `location.hash`의 `code`를 codec으로 적용하고 `run=1`이면 실행. 기존 초안은 덮어쓰기 전에 되돌리기 알림으로 보존 — v1.8.5 '기록 불러오기 되돌리기'와 같은 방식.)
- 의견 스레드.

### 4-4. 공통
- 좋아요·싫어요/신고/정렬/더 보기/빈 상태/로딩/에러 상태는 한 컴포넌트 세트로 세 게시판(의견·티어표·팀) 공유. 티어표·팀 목록의 "공감순"도 같은 점수(좋아요 − 싫어요)를 쓴다.
- 추천순 공식: `score = (좋아요 − 싫어요) / (경과시간h + 2)^0.8`(목록) · 스레드 안 댓글은 단순 `좋아요 − 싫어요` 후 최신순. 새 글이 묻히지 않게 목록만 시간 감쇠.
- **도배 방지 v2(2026-09-28, 사용자 요청 — 욕설 필터 없음)**: 15초 간격·게시판 10분 5개·같은 내용 24시간·반복/링크 도배·티어표/팀 하루 5·사이트 분당 60 초과 시 10분 비상 정지. 표는 `lounge_api/README.md`.
- 신고는 관리자 큐로만 간다(자동 접힘 없음 — 사용자 결정). 관리자 = 사용자 1명.
- 글 언어 자동 감지 저장, 목록 상단 "내 언어만" 토글(기본 끔).
- 링크·이미지 첨부 없음(텍스트 전용). URL은 텍스트로만 표시(자동 링크 안 함) — 스팸·피싱 차단.

## 5. 백엔드 — 정적 사이트의 한계와 선택

GitHub Pages는 정적 호스팅이라 글 저장·공감·신고를 처리할 서버가 반드시 필요하다. 기존 피드백 버튼의 Google Apps Script는 쓰기 전용·응답 확인 불가(no-cors)라 게시판에는 못 쓴다.

| 안 | 구성 | 장점 | 단점 |
|---|---|---|---|
| **A (추천)** | **Cloudflare Workers + D1(SQLite) + Turnstile** | 무료 한도(요청 10만/일, 저장 5GB)로 충분. 서버 코드에서 공유 코드 재판독·이름 부여·도배 제한을 직접 처리. `wrangler dev`로 **DB까지 전부 로컬에서 개발·테스트** 가능. Turnstile = 캡차 없이 봇 차단 | Cloudflare 계정 1개 필요(사용자 생성) |
| B | Supabase(Postgres + RLS) | 실시간 구독, 관리 콘솔 | 익명 쓰기 규칙을 RLS로만 막기 까다로움, 서버 로직(이름 부여·코드 판독)은 Edge Function 별도. 무료 프로젝트 7일 비활성 시 일시정지 |
| C | GitHub Discussions(giscus) | 서버 0 | GitHub 로그인 필수 → "익명의 ○○" 불가. 요구사항과 충돌 |

**결론: A.** 프런트는 지금처럼 GitHub Pages, API만 `lounge-api.<도메인>.workers.dev`.
(참고: 이 백엔드는 공개 사이트용 제3자 인프라이며 Claude 계정 클라우드와 무관하다. 개발·테스트는 전부 로컬 `wrangler dev`에서 하고, 실제 배포는 사용자 확인 후.)

### 5-1. 데이터 모델 (D1)

```sql
devices   (hash PK, created_at, banned INT)
threads   (key PK, kind 'char'|'tier'|'team', ref TEXT)          -- 'char:10441', 'tier:abc', 'team:xyz'
posts     (id PK, thread_key, parent_id NULL, device_hash, anon_char INT, anon_no INT,
           body TEXT, tags TEXT, lang TEXT, build TEXT, likes INT, dislikes INT, reports INT, pin_hash, pin_salt, pin_fail INT, pin_lock_until,
           status 'ok'|'hidden'|'deleted', created_at, edited_at)
tierlists (id PK, device_hash, anon_char, anon_no, title, basis, rows JSON, descr, build,
           likes, reports, status, created_at)
tier_pos  (tier_id, char_id, pos REAL)                              -- 평균 티어 집계용 정규화 위치
teams     (id PK, device_hash, anon_char, anon_no, code TEXT UNIQUE, chars TEXT, -- 서버 판독 결과 '10303,10441,...'
           summary JSON, title, basis, descr, build, likes, dislikes, reports, status, created_at)
team_char (team_id, char_id)                                        -- "이 동료 포함" 필터 인덱스
reactions (target, device_hash, value INT  -- +1 좋아요 / -1 싫어요, PRIMARY KEY(target, device_hash))
reports   (target, device_hash, reason, created_at, PRIMARY KEY(target, device_hash))
```

## 6. 디자인 방향 (v2 원칙 계승 + 라운지 전용)

- **계승**: tokens.css, Pretendard, 라운드 4/6/10, 강조색 1개, 그라디언트·글로우 0, Lucide 아이콘, 이모지 0, 라이트 기본 + 다크.
- **라운지 전용**
  - 시뮬이 "작업대"(밀도 높은 편집)라면 라운지는 "열람실" — 본문 폭 760px, 본문 15px/1.7 줄 간격(※ 크기 6단계 규칙에 15px이 없으므로 14 또는 16 중 목업에서 결정), 스레드는 카드가 아닌 **구분선 목록**.
  - 익명 아바타 = 동료 아이콘. 이게 라운지의 시각적 정체성(사람 대신 동료들이 떠드는 방).
  - 동료 페이지 헤더는 일러스트를 크게 — 갤러리 컨셉의 "작품 앞 게시판".
  - 티어표는 행 라벨 글자 + 얇은 구분선만, 색 띠 없음. 이미지 저장본도 같은 규칙(사이트 외부에서 봤을 때 브랜드 인상이 되는 부분).
  - 5인 팀 프로필은 시뮬의 슬롯 표현과 같은 모양 — 두 창이 한 제품처럼 보이게.
- **모션(v2 기조 — 적극 사용, 장식 반복 금지)**: v2 `motion.css` + `src/motion/index.js`(stagger·flip·rollup·themeFade)를 그대로 쓰고 라운지 전용 연출만 추가. L1 목업 구현분:
  - 화면 전환: View Transitions — 동료 목록의 초상화가 동료 페이지 머리로 이어지는 공유 요소 전환, 나머지는 페이드+8px.
  - 진입: **화면에 들어오는 순간 등장(IntersectionObserver `reveal`)** — 첫 N개 제한 없음, 지연 상한 없음(상한은 긴 목록 끝이 몰려 나오게 함). 위→아래·왼→오 순, 간격 행 40ms·타일 24ms·칩 14ms, 8px·300ms(v2 `.enter`와 동일). 페이지 골격 → 늦게 그려진 목록이 한 시계로 이어짐. 답글도 개별 등장.
  - 필터·정렬: 동료 격자, 팀 목록, **의견 추천순↔최신순 전환 시 FLIP** — 점수 낮은 글이 아래로 가라앉는 게 눈에 보임.
  - 좋아요: 숫자가 방향대로 한 칸 굴러감 + 엄지 아이콘 기울기.
  - 새 의견: 자기 자리로 스크롤 + 페이드인 + 강조 배경이 서서히 빠짐.
  - 티어 편집기: 끄는 동안 실제 칩이 삽입 위치로 이동하고 주변 칩이 비킴(행 간 FLIP), 놓으면 고스트가 칩 자리로 내려앉음.
  - **팀 올리기: 코드를 붙여 넣으면 동료 아이콘이 코드 칸에서 하나씩 날아와 슬롯에 앉음**(70ms 간격) → 이름·속성이 뒤따라 나타남.
  - 시뮬하러 가기: 다섯 명이 차례로 살짝 들렸다 내려오고 페이지가 물러난 뒤 이동.
  - 평균 티어: 기준 전환 시 아이콘이 행마다 순서대로 자리 잡음. 대화상자·메뉴·토스트는 v2와 같은 등장.
  - 움직임 줄이기: 이동 제거·페이드만(uitest 기본값), `LOUNGE_MOTION=1`로 모션 경로 검사.
