## 0. 요약

- 사용자가 실제로 정하는 것은 네 가지입니다. **누가 언제 궁을 쓰는가**, **누가 먼저 움직이는가**, **어느 턴이 예외인가**, **누구에게 맞추는가**. 지금은 이 네 가지가 **표면 10곳**에 흩어져 있습니다: 메인 2곳, 캐릭터 창 3곳, 고급 설정 탭 3개, 비교 팝업 2곳. 궁 타이밍 하나만 봐도 캐릭터 창 계획, 배치 프리셋, 궁극기 사용 방식 탭, 연동 탭, 타임라인, 욱영 전용 토글, 이태호 추가 행동 칸까지 7곳에서 바꿀 수 있습니다.
- 가장 비싼 과업은 피드백에서 나온 "마타야 방어 → 욱영 궁 → 마타야 궁, 평소엔 매 턴 궁"입니다. **46클릭 · 화면 전환 6회 · 표면 5곳**이 들었고, 그중 29클릭은 '모두 궁' 버튼이 없어 칸을 하나씩 누른 것입니다(§2 S5).
- 모드 충돌은 조용히 일어납니다. 타임라인을 켜면 궁극기 사용 방식·연동 탭에는 "쉽니다"라는 점선 안내만 붙고, **컨트롤은 그대로 편집할 수 있습니다**. 바꿔도 결과는 달라지지 않습니다. 또 타임라인을 켜는 순간 연동·사용 방식의 결과는 타임라인에 구워지고, 캐릭터 계획·우선순위·특정 턴은 버려집니다(F07·F08).
- 버그 수준 문제가 두 가지 있습니다. ① 1280·1440 폭에서 길드 제단 패널의 '사용' 스위치와 ✕가 '패치 히스토리' 버튼에 가려서, 실제로 누르면 패치 히스토리가 열립니다(F25). ② 390px 모바일에서 고급 설정 카드가 584px로 넘쳐 '사용' 라벨과 행 버튼이 잘립니다(F19).
- **추천은 B안 '단계형 행동 패널 + 실행 미리보기 격자'**입니다. 기존 저장 계약(우선순위·특정 턴·계획·사용 방식·연동·타임라인)을 1:1로 유지하면서, 흩어진 설정을 한 패널에 순서대로 모으고, 결과를 30턴×5인 격자 하나로 보여 줍니다. A안 '단일 보드'는 이상적이지만, 아래에서 여전히 두 체제(규칙 대 완전 수동)로 갈라져 있어 위험이 큽니다(§5).

## 1. 현재 구성 검증 — 행동 설정 표면 인벤토리

브리프에 적힌 구성은 대부분 맞았지만, 세 가지를 바로잡습니다.
**(a)** 확률 CD 제단 안내와 원클릭 전환은 제단 패널이 아니라 **고급 설정 › 궁극기 사용 방식 탭**에 있습니다. 제단 패널에는 행동 관련 안내나 바로가기가 없습니다(`data-advopen` 생산처는 app.js L3417 한 곳뿐이고, 실측 `hasLink=false`).
**(b)** 캐릭터 창에는 요약만 있는 게 아니라 **30턴 행동 계획(플래너)** 전체와 배치 프리셋 4종, 욱영 전용 '아군 필살 나중', 이태호 추가 행동 칸이 들어 있습니다.
**(c)** 비교 화면의 행동 팝업에서는 궁극기 사용 방식을 **그 자리에서 직접 편집**하지만, 메인 캐릭터 창은 요약과 이동 버튼만 줍니다.

### 시나리오별 관찰

- **S1·S2·S9 — 실행 버튼이 접힌 영역 아래에 있습니다.** 1440×900에서 `#runBtn`은 문서 y=1326이고, 우선순위 목록은 y=782에서 시작합니다. 설정을 하나 바꿀 때마다 400~600px을 오가게 됩니다. S9는 기록 드롭다운(최상단) → 편성 → 로스터 → 실행 순서라 1,913px을 스크롤했습니다.
- **S3 — '특정 턴만 다르게'는 짧지만 턴 칩 30개가 늘 보입니다.** 드래그를 쓰면 3클릭이지만 모바일은 ▲▼만 됩니다. 한 번 선택한 칩을 다시 누르면 그 턴의 순서가 **확인 없이 삭제**됩니다(L2769).
- **S4 — 계획과 방식이 다른 창에 있습니다.** 4·7·10 계획은 캐릭터 창에 있고(3쿨 캐릭터라 기본 계획이 이미 4·7·10…), "그 턴만"(strict)은 고급 설정 궁 탭에 있습니다. 캐릭터 창의 '행동 고급 설정에서 변경'은 **캐릭터 창을 닫고** 모달을 엽니다(L3648). 계획을 다시 확인하려면 모달을 닫고 슬롯을 다시 눌러야 합니다. 궁 탭에서는 5명 중 3명만 보이고, 리카노 행까지 296px을 스크롤해야 했습니다.
- **S5 — 가장 비쌉니다.** 연동 탭에서 앵커·멤버·'방어 →'를 고르는 데 6클릭이 들어 합리적입니다. 하지만 "평소엔 매 턴 궁"(1쿨)은 캐릭터 창 플래너에서만 되고, 마타야 기본 계획이 전부 평타(HOLD_ULT, L57)라 **궁 칸 29개를 하나씩** 눌렀습니다. '모두 궁' 버튼은 없습니다(모두 평타 · 모두 방어만, L4050).
  같은 의도는 궁 탭의 '준비되면 바로' 1클릭으로도 표현될 것으로 보입니다 **(추정)**. 그렇다면 한 의도에 경로가 두 개(29클릭 대 1클릭)이고, 쉬운 쪽은 다른 창에 있습니다. 결과는 4턴 [방어, 필살기] · 5턴 [필살기]로 피드백대로 재현됐습니다.
- **S6 — 원인과 대응이 분리돼 있고, 스위치가 가려집니다.** 제단을 켜는 곳(사이드 패널)과 대응하는 곳(고급 설정 › 궁 탭 '모두 준비되면 바로')이 다른 화면입니다. 1440×900과 1280×800에서는 제단 '사용' 스위치 중심(1323,139)을 누르면 `patch-fab`이 맞아 **패치 히스토리가 열립니다**. 첫 측정에서 실제로 이렇게 실패했습니다(`S6_*` 원자료 metrics.json). 1920×1080에서는 정상입니다.
- **S7 — 타임라인 도구는 강력하지만 단계가 깁니다.** 복사 → 호환 턴 전부 체크 → 붙여넣기의 3단계를 거치고, 격자 칸 하나를 바꾸는 데 3클릭(칸 → 행동 → 닫기)과 엔진 프로브 대기가 듭니다. 한 캐릭터의 30턴을 격자로 바꾸면 약 90클릭입니다 **(추정)**. 켜는 즉시 "적용되지 않는 설정: 특정 턴(3턴) · 캐릭터별 턴 계획(마타야, 리카노)" 경고가 떴습니다. 메인 우선순위·특정 턴은 불투명도 .3으로 남아 자리를 차지합니다(`S7_mainLocked`).
- **S8 — 비교 전용 우선순위 팝업은 메인 A+B의 복제입니다.** 고급 설정은 그 팝업 안에서만 열리고, 모달이 3겹(비교 → 우선순위 팝업 → 고급 설정)으로 쌓입니다. 닫으면 우선순위 팝업으로 돌아옵니다. 반면 비교의 캐릭터 → 행동 팝업(`S8_cmpPlan`)은 계획과 궁 방식이 한 카드에 있어 메인보다 **오히려 낫습니다**. 다만 '궁 간격 맞추기'가 없습니다(L1005 대 L4050).

## 5. 재설계 2안

두 안 모두 공통 원칙을 따릅니다.
- **하나의 진입점.** 행동 결정은 '행동 계획' 한 곳에서 합니다. 캐릭터 창은 "누구인가"(스펙·도장·스킬)만 다룹니다.
- **결과를 먼저 보여 줍니다.** 규칙 설명문 대신 엔진이 계산한 30턴×5인 격자를 보여 줍니다(이미 `API.probe`가 있음).
- **이기는 규칙을 칸에 표시합니다.** 칸마다 "연동 1 / 정해진 턴만 / 예외 턴 / 수동" 출처를 둡니다.
- **덮어쓰인 설정은 편집할 수 없게 합니다.** 완전 수동이 켜지면 규칙 편집기를 실제로 잠그고, 이유와 해제 버튼을 붙입니다(F07).

### A안 — "행동 계획 보드"(단일 표면)

30턴×5인 격자 하나가 곧 편집기입니다. 칸은 두 종류입니다. **규칙이 만든 칸**(흐린 색)과 **사용자가 고정한 칸**(진한 색 + 핀)입니다. 행 머리에는 순서 손잡이 · 궁 방식 칩 · 맞추기 링크를 두고, 열 머리를 누르면 그 턴의 순서 편집기가 열립니다.

```

│ │ 4턴 리카노  평 [궁] 방   │  □ 이후 같은 간격으로 반복                         │

│ ⚠ 7턴은 추가 행동 위치를 직접 정해 '완전 수동 턴'입니다 — 규칙이 적용되지 않음   │
└──────────────────────────────────────────────────────────────────────────────┘
모바일: 격자를 전치(행=턴 30, 열=캐릭터 5 × 56px), 이름은 머리 고정, 칸 누르면 바텀시트
```

- **장점**: 결정 D1~D6이 한 화면에 모이고 "왔다갔다"가 사라집니다. 결과와 편집이 같은 그림이라 규칙 설명문이 필요 없습니다. MOCKUP_PLAN의 기억점인 '30턴 스트립'과 시각 언어가 같습니다.
- **단점**: 정보 밀도가 가장 높아 라이트 유저에게 첫 화면이 무겁습니다. 칸의 의미(규칙 대 고정 대 완전 수동)라는 새 개념을 배워야 합니다.
- **호환성**: 보드는 기존 계약으로 **번역**합니다. 행 칸 고정 → `plan`/`usePlan`, 방식 칩 → `ult`, 열 순서 → `turnOverrides`, 맞추기 → `syncGroups`, 추가 행동 위치 편집 → 그 턴만 `turnPlans`.
  문제는 마지막 경우입니다. 엔진은 지정 턴과 자동 턴이 섞이면 로테이션이 밀려 **전 턴을 materialize해야 안전**합니다(L1785-1787 주석). 그래서 한 턴이라도 추가 행동 위치를 고치면 보드 전체가 완전 수동으로 넘어가야 하고, 겉은 하나지만 속은 **여전히 두 체제**입니다. 공유 코드 v2 · 기록 스냅샷 · `turnPlans` 형식은 그대로 쓸 수 있습니다.
- **구현 위험: 높음.** 칸 ↔ 계약 번역기, 출처 추적(엔진 프로브가 칸별 원인을 돌려줘야 함 → `plan_probe` 확장), 되돌리기 통합이 새로 필요합니다. 하네스 `uitest.js`(행동 셀렉터 60곳) · `uitest_sync.js`(59곳) · `uitest_race.js`를 크게 다시 써야 합니다. v2.0 PLAN의 불변 조건("로직 변경 없음")과 정면으로 충돌합니다.

2. 켤 때 출발점을 **고르게** 합니다. "지금 설정(①②③) 그대로 가져오기"(현 '기존 설정 불러오기' + 연동·방식 포함)와 "역할 기본값에서 시작" 중에서 고릅니다. 비대칭 굽기(F08)를 없애는 조치입니다.

4. '호환 턴 전부 체크 → 붙여넣기'를 '이 턴 구성을 N턴 간격으로 반복' 한 동작으로 합칩니다.

- **장점**: 저장 계약이 **1:1로 그대로**입니다(`priority` · `ult` · `plan/usePlan` · `turnOverrides` · `syncGroups` · `advOn/turnPlans`). 기록·공유 코드·초안·비교 스코프(`openAdvFor` 패턴)를 모두 재사용합니다. 라이트 유저는 ①만 보면 되고, 파워 유저는 ②③과 완전 수동까지 단계적으로 내려갑니다. 피드백 사례가 각 단계에 정확히 대응합니다(레오전 3·6·9·12 = ① 직접+첫 궁 당기기, 마타야 = ① 준비되면 바로 + ③ 방어 →, fed carry = ③).
- **단점**: 미리보기와 편집기가 분리돼 A안보다 한 번 더 봐야 합니다. 완전 수동은 여전히 별도 모드입니다(대신 명시적으로 드러남).
- **측정 기대치 (추정)**: S4는 6클릭·전환 3 → **3클릭·전환 0**(① 리카노 방식 '정해진 턴만' → 실행). S5는 46·6 → **약 10클릭·전환 0**(편성 6 + ① 마타야 '준비되면 바로' 1 + ③ 문장 3). S6은 7·4 → **3·1**(제단 켜기 → 미리보기 안내의 '전원 준비되면 바로' → 실행).
- **구현 위험: 중간.** DOM 이동이 주 작업입니다. 플래너를 캐릭터 창에서 패널 행으로 옮기고, 궁 방식을 요약에서 세그먼트로 바꾸고, 연동을 문장형으로 만들고, 미리보기를 붙입니다. 로직(계획 모델 · 프로브 · 재조정)은 재사용합니다. 새 로직은 ① 미리보기의 칸별 출처 표시(프로브 결과 + 프런트 규칙으로 1차 근사, 정밀판은 `plan_probe`에 `src` 필드 추가), ② 완전 수동 진입 시 출발점 선택 두 가지입니다. 하네스는 `uitest.js` · `uitest_sync.js`의 행동 셀렉터를 갱신해야 합니다. `live_smoke.js`와 `uitest_state.js`는 대부분 상태·함수 기반이라 영향이 적습니다 **(추정)**.
