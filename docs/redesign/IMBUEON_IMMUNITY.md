# 임부언(10410) — 필살기 CD 변동 면역(시한부) 엔진 구현

2026-09-28 · 엔진만 수정했다(`woofia_sim/effects.py`, `woofia_sim/engine.py`). 프런트(v1 `dashboard/`, v2 `dashboard_v2/`)는 손대지 않았다. 아래 §5는 플래너를 고칠 때 넣을 규칙을 제안한 것이다.

## 1. 원문과 해석

필살기와 도장 필살기(`data/skills.json` 10410)의 원문:

```
아군 포지션 1에 위치한 동료의 필살기 CD ${arg1} 감소                    (arg1=3)
아군 포지션 1에 위치한 동료가 필살기 CD 변동 효과에 면역됨(${arg2}턴)     (arg2=3)
(도장) 아군 포지션 1에 위치한 동료의 행동 횟수가 ${arg3} 회복             (arg3=1)
EN: Grant Buddy in Position 1 Immunity to EX Skill CD changes for ${arg2} turn(s).
```

| 항목 | 엔진 동작 |
|---|---|
| 대상 | 임부언이 필살기를 쓰는 순간 **포지션 1에 있는 동료**(`position_1` 대상 규칙 그대로) |
| 순서 | 효과 목록 순서대로 CD −3이 먼저 들어가고, 그다음 면역이 걸린다(같은 필살기 안) |
| 지속 | 3턴 = 버프와 같은 반턴 수명(6반턴). 턴 T 아군 페이즈에 부여되면 **T의 남은 행동, T+1, T+2**까지 유효하고 T+2가 끝나면 풀린다 |
| 막는 것 | 그 동료의 필살 CD를 바꾸는 **모든** `CD_MOD`: 아군이 주는 감소, 자기 스킬의 감소, 제단 1012(행동 시 30% CD−1)·1013(필살 시 30% CD−3), 턴 시작 시 CD 감소, 확률 CD 감소 성공 가정으로 쌓이는 적립 |
| 막지 않는 것 | 필살기를 쓰면 CD가 최대치로 돌아가는 기본 동작, 턴이 끝날 때 CD가 1 줄어드는 자연 충전, 제단 402(최대 CD +1) |
| 다시 걸릴 때 | 이미 면역인 대상에게 임부언이 다시 필살기를 쓰면 **CD −3은 막히고 면역만 새로 갱신된다**(남은 기간과 새 기간 중 긴 쪽, 중첩 없음) |
| 제토와의 관계 | 제토(10441)의 영구 면역(`Immune to EX Skill CD changes.`, 기간 없음)은 종전대로 MARKER에서 `Unit.cd_immune`으로 간다. 이 면역은 외부 조작만 막고 자기 CD 변동은 허용한다. 시한부 면역은 따로 `Unit.cd_immune_turns`로 관리하므로 둘이 함께 있어도 서로 간섭하지 않는다 |

### 가정(사용자 확인 필요)
1. **자기 CD 감소도 막는다.** 원문이 "필살기 CD 변동 효과에 면역"이므로 출처와 관계없이 전부 막는 것으로 해석했다.
2. **제단 402(최대 CD +1)는 막지 않는다.** CD를 바꾸는 효과가 아니라 최대치 규칙이고, 킷 단계(`harness`의 `kit.fatal.cd += 1`)에서 이미 반영된다.
3. **면역 중 재필살 = CD 감소는 막히고 면역만 갱신.** 원문 순서(감소 → 면역)를 따르면 감소가 들어가는 시점에 이미 면역이 걸려 있으므로 막힌다고 추정했다.
4. **성공 가정 적립은 면역 전에 쌓인 몫만 쓸 수 있다.** 면역 중에 생긴 확률 CD 감소 기회는 적립하지 않고 무효로 기록한다. 면역 전에 쌓인 적립은 그때 실제로 성공했을 감소이므로 면역 중에 필살기를 쓸 때도 계속 쓸 수 있다(`_consume_cd_assist`는 그대로). 사용자가 적립 사용까지 면역으로 막는 쪽을 원하면 `_ult_ready`와 `_consume_cd_assist`에 `cd_immune_turns == 0` 조건을 하나씩 넣으면 된다.
5. 대상이 없거나(포지션 1이 비었거나) 임부언 자신이 포지션 1에 있으면(솔로) `position_1` 대상 규칙을 그대로 따른다. 솔로에서는 임부언 자신이 면역된다. UI는 임부언을 1번 자리에 둘 수 없게 막고 있다.

T 4 임부언          필살 → 명계 경비견 아누비로스 CD 변동 면역(3턴)

T 4 명계 경비견 아누비로스  발동 → 자신 필살 CD -1 (CD 변동 면역으로 무효)     ← 1012

## 5. 플래너 영향과 권고 (수정하지 않음)

엔진이 실제 실행 결과이므로 결과·로그·`/api/probe`의 `turn_ready`에는 면역이 자동으로 반영된다. 반면 플래너의 **사전 CD 모델**(격자에서 궁 칸 허용 여부, 성공 가정 표시)은 JS로 다시 구현돼 있어 면역을 모른다. 그래서 P1 캐리가 성공 가정이나 방어 CD 감소로 T+1·T+2에 궁을 당기는 계획을 세우면, **격자는 허용하는데 엔진은 평타로 내린다**(엔진이 쿨 미충족으로 내리는 조용한 불일치).

**모델링이 필요한 범위**: 팀에 임부언이 있고 1번 자리 동료가 임부언이 아닐 때, 그 1번 자리 동료만.

### 권고 규칙 — `dashboard_v2/src/core/plan.js`
1. `imbueonUltTurns(teamArr, turns, env)`에서 파생 헬퍼를 만든다: `cdImmuneTurns(teamArr, turns, env) → Set`. 임부언 필살 턴 T마다 **T+1 … T+(dur−1)**(dur=3이면 T+1, T+2)을 넣는다. 턴 T는 넣지 않는다. 임부언은 역할 순위(SPECIAL 6.0)상 아군 뒤에 행동하므로 캐리의 자기 행동은 면역 전이다. T의 추가 행동은 플래너가 따로 모델링하지 않는다.
   - 참고: `imbueonUltTurns`는 임부언의 핀이나 성공 가정 리듬(`assistFirstUlt`, `effectiveTeam`의 줄)을 보지 않고 `ffat`/`fcd` 주기만 쓴다. 임부언에게 성공 가정이 켜져 당겨진 리듬이면 면역 창도 당겨지므로, `effectiveTeam(...)[임부언].plan`의 '궁' 턴을 쓰는 편이 정확하다.
2. `ultAvail(plan, meta, allyBasics, src, env, immune?)`와 `normalizePlan(...)`에 선택 인자 `immune`(Set)을 추가한다. `immune.has(t)`인 턴에는:
   - `bank += actAmt + (fires ? ultAmt : 0)`를 건너뛴다(성공 가정 적립 없음).
   - 방어 CD 감소(`cd -= red`, `cd -= per * stk`)를 건너뛴다. 스택 축적은 그대로 둔다.
   - `cd = fcd(...)`(필살 후 재설정)과 `cd -= 1`(자연 충전)은 그대로 둔다.
   - 인자가 없으면 종전 동작이다(다른 호출부는 무영향).
3. `planView(slot, i, team, n, env)`: `i === 0 && team`에 임부언이 있고 `slot.id !== IMBUEON_ID`이면 `immune = cdImmuneTurns(team, n, env)`를 `normalizePlan`/`ultAvail`/`okIf` 계산에 넘긴다. `lockUlt`와 `store.pins.ultAllowed`가 이를 따라간다.
4. `assistFirstUlt` / `assistPulls`: 1번 자리 캐리의 첫 당김 궁은 대개 임부언의 첫 필살(≥ `ffat(임부언)`)보다 앞서므로 보통 영향이 없다. 정확히 하려면 3과 같은 `immune`을 넘긴다.
5. **바꿀 필요 없음**:
   - `pinFillKind` / `cycleFill`: 주기 채움은 `fcd`(자연 충전·재설정)만 쓰는데, 둘 다 면역이 막지 않는다.
   - `effectiveTeam`의 fed carry 제외(`fedCarry`): 줄을 안 보내는 이유(캐리의 '평' 토큰 보존)는 면역과 무관하다.
   - 이태호 fed(`taehoFedTurns`/`fedPayload`): 이태호는 CD 변동 효과가 없고 fed 추가 행동은 평타가 기본이다.
