## 6. 발견된 문제와 처리

1. **모이루·히토하 자동 방어가 v2에서 빠져 있었다** — 필살기 칸만 고정되고 엔진이 쿨 미충족으로 밀어냈다. → 이식(메타 기반), v1과 줄·행동 동일.
2. **예외 턴이 모이루를 앞으로 옮기면 CD 모델과 어긋난다**(v1도 같은 한계). 모델은 '아군 뒤에 행동'을 가정한다. 순서를 모델에 넣으려면 `store.env`에 예외 턴을 실어야 해서(store.js는 이번 범위 밖) 대신 예외 턴 저장 시 경고 토스트를 띄운다. 칸이 밀리면 ④ 경고 점과 메인 미리보기에도 드러난다. 후속 권고: `makeEnv`에 `overrides`를 받아 `allyBasicCounts`가 모이루보다 뒤에 행동하는 동료의 보통 공격을 다음 턴 스택으로 넘기게 하면 된다.
3. **란 시너지는 4번 자리 동료가 란보다 뒤에 행동해야 발동한다.** 파미도(우선순위 특수값 4.5)가 4번이면 행동은 같아도 되먹임이 0이다. 툴팁에 명시했다. 경고 자동화는 하지 않았다.
4. **준비되면 바로 + 3턴마다**는 엔진이 고정 보통 공격을 무시한다(의도된 엔진 규칙). 그 방식에서는 두 3턴 프리셋을 흐리게 하고 이유를 보인다.
5. **욱영 체크 경로 차이**: v1은 엔진 플래그(`allyUltAfter`), v2는 연동 그룹이다. 행동은 같고 인접 동료 보통 공격이 연동 순서로 한 칸 앞당겨진다(파미도 필살기보다 먼저). 파미도 도장 버프를 받는 순서가 바뀌므로 데미지가 조금 다를 수 있다. 기존 결정 그대로 두었다.
6. 병합 사전(`i18n/kr.json` 등)에는 새 키가 아직 없다. 8778(개발)은 parts를 읽어 보이지만, 배포 전에 `python tools/redesign/i18n_migrate.py`를 실행해야 한다.
