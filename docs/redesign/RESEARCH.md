## 1. 한 줄 결론

**현 사이트는 구조(편성 → 설정 → 결과)는 표준에 가깝고, 문제는 "선택하지 않은 기본값의 집합"이다.** 다크+골드 그라디언트(버튼 13회), 글로우(23곳), 배경 블롭, 이모지 아이콘(~60개), 카드 4~5겹 중첩, 라벨마다 설명문(안내 박스 15종·em dash 333개), FAB 6개 3색, 스프링 모션 — 이것들이 한꺼번에 있어서 AI가 만든 것처럼 보인다. 대부분은 **토큰·CSS 교체로 없어지고**, 마크업은 FAB·라벨 구조·아이콘, app.js는 결과 차트·비교 화면만 건드리면 된다.

## 2. 조사에서 확정된 원칙 (1단계 토큰의 근거)

| 영역 | 원칙 | 근거 |
|---|---|---|
| 색 | 중립 램프 10~12단계(단계별 역할 고정) + **강조색 1개** + 상태색 3개. 그라디언트 0, 글로우 0, 블러 0(sticky 헤더도 불투명) | Geist·Radix·TDS·Linear 수렴값. 안티패턴 #1~3 |
| 중립 램프 | **OKLCH로 생성, Tailwind zinc와 겹치지 않게** 약간의 온기(warm) | trends §6 주의, Linear 2026·Toss 2025 |
| 다크 | 순수 검정 금지(#111113 → #18181B → #202024, 위로 뜰수록 밝게). 깊이는 그림자 대신 보더+표면 밝기. 강조색은 더 밝고 채도 낮게. 대비 별도 재계산 | M3 tonal, Vercel, Notion |
| 속성색 | 8px 점·16px 아이콘에만. 배경·보더 전체 칠하기 금지. **선택 상태는 강조색 2px 링**(공통). 차트 색은 속성색과 분리 | trends §5 "갤러리 벽" |
| 타이포 | Pretendard Variable, 굵기 400/500/600, 크기 6단계(12/13/14/16/20/28), 수치 tabular-nums, 20px↑ 자간 −0.01em | trends §6.4. 현재 22단계 → 6 |
| 간격·라운드 | 4px 기반. 라운드 4/6/10/full 네 값, 중첩 시 안쪽이 작게. 보더 1px 저대비 | M3·Stripe. 현재 radius 22종 → 4 |
| 그림자 | 떠 있는 요소(드롭다운·모달)에만 중립색 약하게. 패널은 보더만 | Stripe |
| 모션 | 100/150/200/300ms + `cubic-bezier(0.2,0,0,1)`. 등장 decelerate·퇴장 accelerate(퇴장이 짧게). 바운스·overshoot·무한 펄스·hover translateY 금지. reduced-motion: 이동 제거·150ms 페이드만, 전역 0.01ms 리셋 금지 | M3·NN/g. 현재 `pop` 스프링·stagger·펄스 3종 제거 |
| 위계 | 라벨만 보이게, 설명은 ⓘ 툴팁/펼침. 공개 단계 2단계 이하. 그룹은 간격 → 선 → 박스 순. **기본값에서 바뀐 설정만 표식+초기화** | NN/g progressive disclosure, Refactoring UI |
| 컨트롤 | 세그먼트 5개 이하·등폭(6개↑는 select). 슬라이더 옆 직접 입력. 터치 타깃 44px. 포커스 링 2px 전역. 토글 input은 시각적 숨김(display:none 금지) | HIG, WCAG, audit 높음 항목 |
| 카피 | 구체 동사+명사. 친근체·이모지·"마우스를 올려" 제거. em dash 남발 제거 | 안티패턴 #10~12, audit #8·#14 |

## 3. 정보 구조 결정: **A안(구조 유지) + B안 일부 차용**

사용자 방향("구조는 괜찮다")과 벤치마크 결론이 일치한다. 2열 유지, 다음만 바꾼다.

| 변경 | 출처 패턴 | 효과 |
|---|---|---|
| 설정 열을 **요약 헤더 아코디언**으로("▸ 기본 반복 50 · 30턴", "▸ 더미 무 · 적 1 · 피격 5") | P1 Raidbots·Genshin Optimizer | 편성 → 실행 거리 1스크린. 설정이 조용해짐 |
| **실행 버튼 sticky**(데스크톱 설정 열 하단 / 모바일 하단 고정 바 + 마지막 결과 칩) | P3 | 첫 화면 밖 실행 버튼 문제 해결 |
| FAB 6개 → **상단바로 흡수**(기록 ▾ · 조합 비교 · 가이드 · ≡ 메뉴{패치 히스토리·피드백·언어·테마}) | audit 치명 ② | 겹침 제거 + AI스러움 최대 감소 |
| 로스터: 검색 + 속성/직업 필터 + 인원 수 + 초기화, 선택 캐릭터에 슬롯 번호 배지 | P7 Prydwen·Overframe | 44명 탐색 |
| 실행 후 **결과로 자동 스크롤**, 모바일 **섹션 점프 칩**(편성·설정·결과·로그) | B안 차용, Google Ads 목차 | 모바일 4,350px 스크롤 대응 |
| 결과: 헤드라인 1개 + 밴드, **기준 문구 통일**("평균 50회 · 로그는 샘플 1회"), 턴 차트에 축·캐릭터별 색, 막대 탭 → 로그 행, 로그 기본 접힘 | P4·P5·P6, audit 중간 | 중앙값/평균 혼재 해소 |
| 충돌 경고를 모달 안이 아니라 아코디언 헤더 배지(⚠1)로 | P13 | 발견성 |

## 5. 컨셉 후보와 추천

세 후보 모두 §2 원칙을 지킨다. 차이는 "온도"와 밀도다.

| | A. 작업대 (Workbench) | B. 종이 (Paper) | **C. 갤러리 (Gallery) — 추천** |
|---|---|---|---|
| 인상 | Linear·Geist. 서늘한 중립, 13px 밀집, 보더 위주 | Apple·Stripe. 따뜻한 오프화이트, 여백 넓음, 타이틀 위주 | 두 축의 중간. **약간 따뜻한 중립 램프 + 넓지 않은 여백**, 일러스트가 주인공 |
| 강점 | 도구답다, 정보 밀도 최고 | 읽기 편하고 고급스럽다 | 44명 일러스트(고채도)가 중립 벽 위에서 정돈됨. 모바일 밀도와 데스크톱 밀도 양립 |
| 약점 | "개발자 도구" 인상, 게임 유저에게 차갑다. 다크 모드가 AI 다크 SaaS와 겹칠 위험 | 밀집 설정 패널과 안 맞음, 화면이 길어짐 | 특징이 약해 보일 수 있음 → 로고·타이포 리듬으로 보완 |
| 강조색 | 파랑 | 짙은 남색 또는 진녹색 | **파랑 계열 1개(OKLCH h≈255, Tailwind indigo·Toss blue와 다른 값)** — 일러스트의 주조색(주황·금·보라)과 보색 관계라 선택 링·버튼이 일러스트와 안 섞임 |

추천 **C**. 근거: (1) 조사 §5 "갤러리 벽" 원칙에 가장 직접 대응, (2) 모바일 비중 높은 게임 유저와 데스크톱 반복 사용자 모두에 맞는 중간 밀도, (3) 안티패턴 #13(Tailwind 기본값)과 A안 다크의 위험을 피함. 강조색 후보 2~3개는 2단계 목업에 스와치로 나란히 놓고 최종 결정한다.

로고: 컨셉 확정 후 별도 제작(사이트 고유 워드마크+심볼, SVG). 심볼은 레이어 스프라이트로 만들어 첫 로드 인트로(1회)와 결과 등장 앵커에만 사용. 게임 타이틀 로고는 쓰지 않는다.
