# 지금 시스템은 어떤 모양인가 — 정리와 나누기 상의용

작성 2026-09-28. 구현 전 상의용. 용어는 GLOSSARY 기준.

## 1. 한 장 요약

시뮬레이터가 실제로 결정하는 것은 딱 세 층이다.

```
[누구]   팀 5명 + 육성(레벨·스타·적합도·도장·제련)                         ← 팀 편성 · 육성 창
[조건]   반복·턴 / 적(속성·수) / 받는 데미지 / 방탈출 제단                   ← 전투 조건
[행동]   턴마다 누가 어떤 순서로 무엇을 하는가                                ← 행동 계획
          규칙(자동)  →  고정(사용자가 못 박은 칸·턴)  →  엔진이 실행
```

엔진(파이썬)은 바뀌지 않았다. 바뀐 것은 **[행동] 층을 사용자에게 보여 주고 만지게 하는 방식**이고, 지금 그 방식이 한 화면에 너무 많이 나와 있다.

## 2. [행동] 층의 실제 구조 (v2.1 core 기준)

엔진에 들어가는 행동 입력은 4가지뿐이다. 나머지 UI는 전부 이 4가지를 만드는 도구다.

| 엔진 입력 | 뜻 | 누가 만드나 | 기본값 |
|---|---|---|---|
| **순서** (`priority`, `turnOrders`) | 한 턴 안에서 누가 먼저 행동하나. 특정 턴만 다른 순서(예외 턴) 가능 | 행 순서 ▲▼ / 턴 편집 | 포지션 규칙(보조→방해→치료→수호→전사) |
| **필살기 방식** (`ult.mode` + `assist` + `keepDef`) | 동료마다: 자동(역할 기본 리듬) / 정해진 턴만 / 준비되면 바로. 옵션: 확률 CD 감소 성공 가정, 방어 턴 유지 | 행 select + ⋯ 메뉴 | 자동 |
| **맞추기** (`sync`) | "A가 필살기 쓰는 턴에 B는 앞/뒤/방어 후 추가 행동에서 필살기, 평소엔 …" 최대 3그룹 | 문장형 편집기 | 없음 |
| **고정** (`rotation` 줄 = 핀, `turnPlans` = 잠긴 턴) | 규칙을 무시하고 못 박은 것. 핀=한 동료의 특정 칸(그 동료의 30턴 줄로 전달), 잠긴 턴=그 턴 전체(순서·행동·추가 행동 위치) | 격자 칸 클릭 / 턴 편집 | 없음 |

엔진 규칙: 잠긴 턴은 그대로 실행 → 핀이 있는 동료는 그 줄대로(쿨 안 되면 폴백) → 나머지는 순서·방식·맞추기로 자동. 즉 **네 가지는 동시에 살아 있고 위에서 아래로 이긴다.** 이것이 v1(규칙 vs 완전 수동 양자택일)과 달라진 핵심이며, 파워유저 요구 #24의 답이다. 저장 형식은 v1 호환(옛 기록·코드는 자동 변환).

## 3. 사용자 유형별로 실제로 필요한 것

| 유형 | 하는 일 | 필요한 화면 | 비율(추정) |
|---|---|---|---|
| **A 라이트** | 편성 바꾸고 실행, 숫자 비교 | 팀 편성 · 실행 · 결과. 행동은 기본값 | 대부분 |
| **B 중급** | 필살기 리듬을 조금 조정(누구를 준비되면 바로로, 순서 바꾸기), 제단 켜기 | 행 5개(순서·방식) + 제단 스위치 + 결과 미리보기(읽기) | 일부 |
| **C 파워** | 방탈출 축 설계: 쿨감 제단·맞추기·특정 턴 고정·성공 가정, 결과를 턴 단위로 검증 | 격자 편집·턴 편집·⋯ 옵션·맞추기·제단 세부 | 소수(피드백 #22~29 사용자) |

지금 화면은 B와 C의 도구가 **같은 패널에 토글 하나로** 붙어 있어서, A·B에게도 격자·범례·설명문이 보인다. 그래서 무거워 보인다.

## 4. 어떻게 나눌지 — 세 가지 안

### 안 1. "화면은 이전 목업 그대로, 파워 도구는 별도 화면"
- 메인 = 2단계 목업 확정본(팀 편성 → 행동 계획 = ①순서와 필살기 ②맞추기 요약 한 줄 + **읽기 전용 미리보기** → 전투 조건 → 결과). 예외 턴·핀·잠금·성공 가정·방어 턴 유지·쿨감 제단은 메인에 **없다**.
- 「행동 세부 설정」 버튼 하나 → **전체 화면(시트)**에서 지금 만든 격자 편집기·턴 편집·⋯ 옵션·맞추기 편집·쿨감 스위치를 전부 제공. 닫으면 메인 미리보기에 결과만 반영되고, 무엇이 고정됐는지는 행 끝에 작은 배지("고정 3", "성공 가정")로만.
- 장점: 메인이 목업만큼 조용하다(사용자가 마음에 들어 한 모양). 파워 도구는 이미 구현된 것을 옮기기만 하면 된다. 단점: 파워유저는 매번 시트를 연다(한 번 열면 그 안에서 다 됨).

### 안 2. "메인은 라이트 전용, 행동 계획 자체를 별 페이지로"
- 메인 = 팀 편성 · 전투 조건 · 결과. 행동은 "기본값 / 사용자 설정 있음(요약 한 줄)"만 표시.
- 행동 계획은 상단 탭(시뮬 | 행동 계획 | 팀 비교)으로 분리된 페이지. 거기서 B·C 도구 전부.
- 장점: 메인이 가장 단순. 단점: B 사용자가 "준비되면 바로 하나만 바꾸기" 위해 페이지 이동. 목업 구조(한 페이지)에서 벗어남.

### 안 3. "지금 구조 유지 + 시각 정리만"
- 격자를 기본에서 접고(행 5개만 보이고 「미리보기 펼치기」), 범례·설명문 제거, 세부 설정을 토글 대신 시트로.
- 장점: 작업량 최소. 단점: 여전히 한 패널에 층이 많아 다시 무거워질 위험.

**추천: 안 1.** 사용자가 마음에 들어 한 목업의 모양을 메인으로 되돌리고, 이번에 만든 파워 도구(엔진 연결까지 검증됨)는 시트 하나로 밀어 넣는다. "쓸 사람은 여기서 써라"에 정확히 맞는다.

## 5. 안 1로 갈 때 화면별 내용 (상의용 초안)

| 화면 | 들어가는 것 | 안 들어가는 것 |
|---|---|---|
| 메인 · 행동 계획 패널 | 행 5개(순서 ▲▼, 필살기 방식 select: 자동/정해진 턴만/준비되면 바로) · 맞추기 요약 한 줄("임부언 → 아누비로스 1개") · 읽기 전용 30턴 미리보기(범례 없이 색만, 호버 시 툴팁) · 「행동 세부 설정」 버튼 · 행 끝 배지(고정 N·성공 가정·방어 턴 무시) | 격자 편집, 턴 머리 편집, ⋯ 메뉴, 프리셋, 쿨감 스위치, 전원 버튼, 설명문 |
| 행동 세부 설정 시트(전체 화면) | 위 격자 편집기 그대로(핀·잠긴 턴·턴 편집·프리셋), 행 ⋯ 옵션(성공 가정·방어 턴 유지·욱영/이태호), 맞추기 문장형 편집, 쿨감 제단 스위치·전원 준비되면 바로·전원 성공 가정, 되돌리기 | — |
| 전투 조건 · 방탈출 제단 | 스위치 + 요약("꺼짐 / 쿨감 제단만 / 사용자 구성") + 「층별 점등 설정」 | 원클릭 버튼(세부 설정 시트로) |
| 육성 창 | 지금처럼. 「행동 세부 설정에서 이 동료 보기」 링크 | 행동 관련 편집 |

기록·공유 코드·팀 비교는 그대로(비교의 「행동 계획 편집」은 같은 시트를 스코프로 연다).

## 6. 결정해 주실 것
1. 나누는 방식: 안 1 / 안 2 / 안 3 (또는 다른 기준)
2. 메인 미리보기 격자를 **읽기 전용으로라도 둘지**, 아예 빼고 "고정 N" 배지만 둘지
3. 맞추기(연동)를 메인 요약 한 줄로 둘지, 세부 설정 안에만 둘지
